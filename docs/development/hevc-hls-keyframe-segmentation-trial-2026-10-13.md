## Observed evidence

- Medicus II source HEVC Main, 1920x800, AAC 6 channels, average 24 fps; reported severe stuttering on the Hisense despite video copy.
- Runtime FFmpeg uses `-re -c:v copy -c:a aac -ac 2 -hls_time 4 -hls_flags delete_segments+split_by_time+temp_file`.
- The observed fMP4 segments 223 and 225 had no keyframe, segment 224 had a keyframe 0.86s after its start. Source has approximately one keyframe per second.
- These findings establish non-keyframe-aligned segmentation, not that it is the unique cause of stuttering. The decoder may retain reference pictures across fragments.
- Solo 3840x2160 HEVC Main10 has smooth playback on installed VIDAA b20261013.2, but startup is approximately five seconds and seek/audio selection are not yet working.

## Experimental scope and acceptance

The experiment changes **only** the H265 fMP4 video-copy command to keyframe-oriented FFmpeg HLS segmentation; it does not remove `-re`, force encode, loosen resume sync safety, change MPEG-TS or H264 copying, or install a daemon. Unit coverage checks all relevant argv and denial of copy resume.

Next evidence is an isolated media packaging test that compares actual fMP4 fragment boundaries and playlist/segment retention for both Medicus II and Solo, followed by an explicitly approved hardware acceptance of any backend candidate. `independent_segments` expresses an FFmpeg packaging assertion and is NOT independent validation that the resulting HEVC fragments start with usable random-access pictures. Do not deploy based on argv tests alone. Keep live services and recordings untouched.

**Decision:** do NOT enable keyframe HLS for all H265/fMP4 streams. The original command-builder regression at `827684e` passed before this safety gating change; retest the **new HEAD** before referring to regression success. A/B measurements demonstrate marked-keyframe fragment boundaries, not that changing the segment policy cures the Hisense stuttering. Before any device trial, design an evidence-driven GOP policy that cannot regress Solo and add a runtime selection path with explicit tests. No production deployment has occurred.

## Probe-contract review and next implementation slice — 2026-10-13

Verified source `core/media/include/MediaCapabilities.h`: `MediaVideoStreamDescriptor` exposes `framesPerSecond`, dimensions, HDR, pixel format and time base, **but no GOP length, per-frame random-access map, keyframe interval or probe confidence**. `MediaPresentationProfile` likewise carries no source-keyframe evidence. FPS and HEVC Main/Main10 do not predict GOP length. The real HLS provision call in `RecordingMediaSessionRuntime.cpp` only receives a resolved profile plus a source segment list and calls `FfmpegHlsCommandBuilder().build(resolvedProfile)` with the experimental argument omitted.

Therefore automatic selection by codec, FPS, profile, resolution or HDR is explicitly prohibited. The next slice must first introduce an **evidence-based source keyframe probe** tied to source fingerprint/session identity (stale and partial evidence fail closed), with upper bound for probe cost, timeout and sample duration; distinguish marked keyframes from independently decodable HEVC random-access points. Then add narrowly scoped eligibility (e.g. multiple consecutive GOP intervals fitting a bounded target with an unknown/long-GOP fallback to legacy) and test Medicus-like short GOP, Solo-like long GOP, sparse/ambiguous keyframes, seek offsets, changed recordings and live. Only after that should `RecordingMediaSessionRuntime::provisionHls` be wired for explicit eligible H265 fMP4 copy sessions, with telemetry and rollback. ## Real source probe failure diagnosed — 2026-10-13

Operator tested the exact HEVC TS source from Medicus II via a relative `source-000001.ts` link and safe ffconcat manifest. The real sampler returned `process_failed`. A matched read-only subprocess comparison confirmed `RLIMIT_AS=256 MiB` caused `Failed to reallocate parser buffer` / `Cannot allocate memory` and zero packets. With **no RLIMIT_AS**, FFprobe succeeded (exit 0) and returned 721 video packets. This establishes an unsuitable **virtual-address-space** limit; it is not a measurement of physical RAM consumption.

Fix `ecf243d95a75cbd5383ce9785997343060512f3e` replaces `MediaProcessLimits{256 * 1024 * 1024, 6}` with `MediaProcessLimits{0, 6}` for only the experimental GOP sampler. The existing MediaProcessRunner still enforces five-second wall timeout, six CPU seconds and 256 KiB captured stdout, and the probe remains read-only. Neither the runtime nor the system daemon is modified. This change needs a fresh real-data rerun against its exact source/head before marking acceptance. A successful probe still does not establish HEVC random-access trust or turn on keyframe segmentation.

## Operator-scoped live-session pilot — not deployed

Implementation on this branch now connects `RecordingMediaSessionController::createSessionInternal` to a **fingerprint-scoped operator opt-in**, exclusively for H265/fMP4 video-copy recordings at initial HLS start. It is **disabled by default**. The variable `VDR_SUITE_HEVC_HLS_TRIAL_SOURCE_FP` must equal the exact immutable fingerprint returned by source resolution for the single operator-reviewed recording; it is never accepted from the TV or untrusted request. For an eligible session, controller inspects recording identity before and after a bounded ffprobe sample, rejects growing or changed recordings, uses the short-GOP policy, and passes the evidence only to `provisionHls`. All ordinary sessions, including Solo, continue legacy segmentation; resume and live remain unchanged.

**Trust boundary:** The exact-fingerprint operator allowlist denotes the operator's independent HEVC-fMP4 source-specific segment/RA review. The sampler only verifies packet-level keyframe flags, not HEVC NAL type. Enabling the pilot on arbitrary fingerprints without separate source-specific verification is not valid. In particular, there is NO automatically validated HEVC-IDR/CRA checker and NO general automatic GOP policy approval.

Performance: a targeted session may incur one bounded 5-second probe on the playback-start path. No scan runs on non-allowlisted sessions; an isolated pilot is appropriate to evaluate Medicus responsiveness before designing a precomputed cache. Failure or timeout falls back to legacy; there is no daemon-configuration or production restart in this branch. Code changes are untested on the full controller and runtime test suite until the next isolated candidate build.
