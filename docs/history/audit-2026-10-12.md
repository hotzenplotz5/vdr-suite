### Relative-link method and limitation

For the ten relocated architecture/July source snapshots (excluding their current archive README indexes), relative non-HTTP, non-fragment Markdown link targets were resolved against each file's **present** directory and the exact baseline Git tree. The 142 failures therefore measure *post-relocation navigation*, not broken original source at its original historical path. The result counts **link occurrences, not unique target paths**, and does not measure remote URLs, anchors or current runtime behavior.

The repository's [Markdown checker](../../tools/check_docs.py) deliberately skips relative-link checking for paths with a `history` directory component, to preserve immutable source snapshots. A green documentation CI therefore **cannot** certify navigation from inside those snapshot bodies. New navigation should go in their surrounding indexes rather than silently rewriting archived links.

- A standalone full-repository review of old, non-directory-classified phase closeouts, miscellaneous root docs, source-vs-runtime claims and remaining 740-file semantic coverage would require its own bounded inventory and historical-baseline verification. This audit neither invents a completion percentage for that work nor suggests that green CI proves such a review.
- If navigable inline links inside frozen snapshots become a product requirement, choose and review an explicit **non-mutating companion/link map** or a separately justified archival rewrite policy first. Merely fixing paths in a historical source snapshot is not a preservation-neutral edit.
