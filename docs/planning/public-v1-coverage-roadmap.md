## Reading the states

- **Public-v1 implemented** means a route exists in source; it does **not** mean the operation is installed, granted or verified against a real VDR.
- **CI** is reported for an exact commit only; **installed** means a separately checked yaVDR daemon; **Hisense** means actual TV functional acceptance. Never conflate them.
- Device clients authenticate using paired Device credentials and explicit backend grants. Browser/administrator APIs have different CSRF and ownership rules.
- Public-v1 is an independent, versioned and secured contract, **not** an alias for `/api/vdr/...`. Native Timer, TimerIntent, TimerAssignment, NativeTimerBinding, SearchTimer and durable Operation are different resources.
- Routes listed below are verified from `api/rest/src/PublicApiRuntime.cpp`, `api/rest/src/ApiRouter.cpp` and the [OpenAPI subset](../../api/openapi.json). Paths described as **proposed** are *not* implemented.
- The machine-readable OpenAPI snapshot has **55 method operations on 43 templates** at the audit baseline. The historical **41/30** in `api/README.md` was stale; **41 audited contracts** may still be a narrower gate in `tools/check_public_v1_openapi.py`, not the file's actual operation count.

### Device grant admission (2026-10-18)

The source audit found that `SecurityHttpGate` requires `timers.create@backend`, but the normal Device administration allowlist originally exposed only `timers.view`. This prevents a paired VIDAA client from obtaining CREATE permission through normal administration. The Slice-1 permission correction makes **only `timers.create` on a concrete backend** assignable, updates Device `supportedPermissions`, and tests real grant/revocation with Device authentication. It does not enable an unconfigured EPG TimerIntent submit or authorize native writes by itself.
