## Compatibility of the selected `-or-later` option

The selected `GPL-3.0-or-later` does **not** introduce a new incompatibility in the matrix compared with distributing the relevant work under GPLv3: GPL-2.0-only code is still incompatible *when incorporated into the same derivative program*, and GPL-2.0-or-later code can be used under its GPLv3 option while retaining original notices. LGPL/permissive dependencies require their own conditions, and native VDR plugin linking needs separate verification. The future-version option does **not** override third-party restrictions, prove authorship, or authorize arbitrary relicensing of GPLv2-only code.

### Legally material distinction

- **Copied/adapted code:** the original notice continues to govern copied material; request a separate license grant or replace incompatible fragments.
- **Same program / linking:** GPL version conflicts can matter, particularly for native SuiteBridge/VDR interaction and linked dependencies; classify the actual build, not its marketing description.
- **Separated processes over HTTP/SVDRP:** ordinary protocol communication does not by itself relicense either process. Evaluate unusually intimate coupling/copying separately.
- **Merely using tools:** a CLI-installed FFmpeg does not automatically pass its license to independent source code; distribution of the FFmpeg executable is assessed independently.

GNU GPL FAQ: https://www.gnu.org/licenses/gpl-faq.html (especially GPLv2-only vs GPLv3 and combined works).

### Upstream VDR license finding

The inspected upstream [VDR `vdr.c`](https://github.com/vdr-projects/vdr/blob/master/vdr.c) begins with Klaus Schmidinger's copyright notice and explicitly allows **GPL version 2 or (at your option) any later version**. The upstream [VDR `plugin.h`](https://github.com/vdr-projects/vdr/blob/master/plugin.h) refers to `vdr.c` for copyright information. Therefore the core VDR plugin API is **not shown to be GPL-2.0-only**; a GPLv3-licensed SuiteBridge plugin has an available GPLv3 compatibility path with this upstream. Verify the exact VDR release used in distributed builds and any third-party plugin-to-plugin source interfaces separately. No upstream VDR code is relicensed by this project.

### TVScraper in-process source interface

`vdr-plugin-suite-bridge/suitebridge_tvscraper_adapter.cpp` directly includes `services.h` and translates TVScraper media types (`cTvMedia`, `tvType`, `eCharacterType`, `eOrientation`) into SuiteBridge types. Unlike HTTP-based integrations, this is **an in-process VDR service interface** and must be considered in the native compatibility analysis. The TVScraper upstream README explicitly allows GPL-2.0-or-later, so its **GPLv3 option is available**, but the in-tree `vdr-plugin-suite-bridge/services.h` explicitly identifies upstream `MarkusEh/vdr-plugin-tvscraper` and has been compared to upstream `services.h`. It is treated as an adapted upstream service contract, with a file-scoped `SPDX-License-Identifier: GPL-2.0-or-later` and author/upstream attribution. The available GPLv3 option allows use alongside VDR-Suite GPLv3 code; the original upstream license is preserved. Do not classify this particular integration as mere HTTP communication.
